# BUS YATRA — Android build (Capacitor wrapper)

The game itself is the Arqadex web game (`public/bus-yatra/`, Three.js).
This wrapper packages the built site (`out/`) into a real installable Android
app with a **native landscape lock** — the OS forces landscape at launch, not
a CSS trick.

## What is already in this repo

- `capacitor.config.ts` — app id `com.arqadex.busyatra`, name `BUS YATRA`,
  `webDir: 'out'`, server `androidScheme: 'https'`.
- `android/` — the full Capacitor Android project (generated by
  `npx cap add android` with Capacitor 7.6.10).
- `android/app/src/main/AndroidManifest.xml` — the only hand edit:
  `android:screenOrientation="landscape"` on `.MainActivity`.
- `android/app/src/main/assets/public/` — the built site, synced by
  `npx cap sync android` (re-run after every web rebuild).

## Build it (Android Studio — the reliable route)

1. Open this repo's `android/` folder in Android Studio.
2. Let it sync Gradle (AGP 8.6.x, Gradle 8.11.1, JDK 17, compileSdk 34).
3. Run **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.
4. The debug APK lands at
   `android/app/build/outputs/apk/debug/app-debug.apk` — install it on any
   phone; it opens straight into landscape.

## Build it (command line)

```sh
export JAVA_HOME=<path to JDK 17>
export ANDROID_SDK_ROOT=<path to Android SDK, platform 34 + build-tools 34.0.0>
cd android
./gradlew assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Re-sync the web assets first whenever the game changes:

```sh
npm run build
npx cap sync android
```

## Known blocker (this VM only, 2026-11-07)

On the build VM the Gradle daemon starts and listens, but the Gradle
client cannot complete its handshake with it: the client connects to
`127.0.0.1:<daemon port>`, dispatches the Build request, and the receive
fails ~18 ms later with "Could not receive a message from the daemon".
The daemon never logs the incoming Build command. The socket itself works
(a raw TCP connect succeeds), and the same failure repeats with a fresh
daemon, smaller heap, SerialGC, and `--no-daemon`. It is an environment
issue (daemon threads starved on the throttled VM), not a project issue —
the project, manifest, and assets are all verified correct. Build it in
Android Studio or on any normal machine.

## Releasing

For a Play Store release, generate a signing keystore and a
`keystore.properties`, then run `./gradlew bundleRelease`. The debug APK
is unsigned and is for sideloading/testing only.
